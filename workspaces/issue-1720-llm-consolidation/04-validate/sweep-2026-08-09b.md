## 5. Decision points — judgment calls, for co-owner direction

### Decision A — where does `credential_scrub` live? **(gates ~1,959 sites)**

`credential_scrub` is in `kaizen.utils`; kaizen is an **opt-in extra** of the slim core.
Verified: 0 files in `src/kailash` and 0 in `nexus` import any scrub helper — they cannot.

**Recommend: relocate to `kailash.utils`**, beside `secure_logging.py` which this branch
already added there.

- **Pros** — the only option that neither duplicates a security helper nor breaks slim-core;
  the precedent is already set inside this PR for exactly this reason; unblocks two packages.
- **Cons (real)** — moves a 1,200-line module with dense ReDoS-analysed commentary across a
  package boundary; kaizen must then import from core, so kaizen's own release couples to a
  core release; and the move itself is a `/redteam`-worthy change on a security surface.
- **Alternatives** — duplicate (guarantees the drift the shared helper exists to prevent);
  make kaizen a hard core dependency (contradicts slim-core, documented in `CLAUDE.md`).

### Decision B — merge the branch now, or hold for the three security fixes?

**Recommend: merge now, scoped honestly.** The PR body already says it swept one tree of four
and names the blocker.

- **Pros** — 240 commits of verified work stops aging; six worktrees stop drifting from main;
  #2013/#2014/#2015 get clean, individually-reviewable PRs.
- **Cons (real)** — three live security controls stay broken in `main` for another cycle, and
  the branch's own PR body then documents open defects in shipped code.

### Decision C — Sweep-N on #2003 / #2005 (third cycle) and #1995

**Recommend: re-defer #2003 and #2005 with fresh anchors; implement #1995.**

- #2003 / #2005 — **Pros of re-defer:** both are genuinely off the shipped path and the
  security queue outranks them. **Cons:** third consecutive re-defer is the decay pattern
  `value-prioritization.md` Origin documents (7-of-7 decayed rather than picked up); a fourth
  should trigger close-or-implement, not another defer.
- #1995 — **Pros of implement:** 2,022-file pre-commit rewrite makes every diff in this repo
  noisy and is a standing hazard to any future sweep's signal. **Cons:** a 2,022-file
  formatting commit is itself unreviewable and will conflict with all six worktrees — so it
  MUST land after Decision B, not before.

**Per `value-prioritization.md` MUST-4 none of these may be closed as `not_planned` without
