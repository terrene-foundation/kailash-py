### Still open — BUG

**`[BUG][MED]` `_URL_WITH_AUTH` over-redacts compact-JSON error bodies.**
`credential_scrub.py:194-196`. Both userinfo halves are `[^\s]`, greedy, with
whitespace the only terminator. Provider 4xx bodies are compact JSON with no
whitespace, so a match runs from `https://` through the LAST `@` in the run and
collapses the error text, the docs link, and the JSON structure into
`https://[REDACTED-CRED]:[REDACTED-CRED]@example.com"}`. Security direction is
safe; diagnosability is the loss, on the exact surface `body_snippet` exists to
provide. NOT fixed this session and NOT reclassified — it stays BUG.
Fix: exclude JSON structural chars (`" { } ,`) from the userinfo classes; they
are never legal unencoded in userinfo per RFC 3986, so this keeps the
`@`-inside-password coverage while stopping at the JSON field boundary.

### Decision B — the MCP stack is undeclared

`kailash-nexus/pyproject.toml` pins **neither** `mcp` nor `fastmcp`, so which
MCP tier nexus uses depends on whether an undeclared optional package happens
to be installed. Measured this session: `fastmcp` 3.x is **not co-installable**
— it requires `starlette>=1.x`, which breaks the pinned `fastapi` and takes the
repo's imports down with it.

- **B1 — declare and pin the supported stack (recommended).** Pro: behaviour
  stops depending on resolution order; the incompatibility becomes a stated
  constraint instead of a trap. Con: someone must decide which tier is
  supported, and pinning `mcp` narrows consumer freedom.
- **B2 — leave unpinned.** Pro: zero work. Con: the next person to install
  `fastmcp` breaks their environment exactly as I did, with no signal that it
  was unsupported.

**Recommendation: B1.** Confidence: HIGH on the incompatibility (measured),
MEDIUM on which tier you want as canonical.
